# Archetypes

Vibe Mill produces apps that fit one of twelve archetypes. The matcher's job is to score each input against all twelve and either pick the highest scorer (if above threshold 7) or reject. The generator's job is to produce code that fits the chosen archetype.

This document describes each archetype at the conceptual level. Implementation details (slot structure, codegen prompt fragments) are derived from this document by `MATCHER.md` and `GENERATOR.md`.

## V0 scope

V0 implements only **Tracker**. The other 11 archetypes are stubbed in code but the matcher should never select them (they will always score 0 in V0). The full archetype library is enabled in V1.

## Archetype 1: Tracker

**When it fits:** the input describes an ongoing event with quantifiable data points, geographic distribution, or temporal progression.

**Examples:** disease outbreaks, election results, regulatory deadlines, sports seasons, financial markets, public health metrics.

**App shape:** map plus counter plus timeline plus news feed. The user lands and sees current state at a glance.

**Slots the LLM fills:**
- Title and tagline
- Color theme (primary / accent / background)
- The data definition (what entities are being tracked, what attributes each has)
- The aggregate counter values (total cases, total deaths, etc.)
- The map regions and their statuses
- The timeline events
- The "last updated" copy

**Fixed by us:**
- Layout shell (header, main, footer)
- The chart and map component primitives (lib/components)
- The footer disclaimer ("Generated by Vibe Mill...")
- The Tailwind config

**Failure modes to expect:**
- Hardcoded sample data presented as if real
- Charts that visualize nothing (empty data)
- Map regions with placeholder coordinates

These failure modes are acceptable. They are part of the artifact.

## Archetype 2: Parody UI

**When it fits:** the input involves a named entity (a person, an organization, a system) with a body of recently-released or leaked content that has a familiar native interface.

**Examples:** Epstein emails (Gmail), declassified UAP files (intel analyst desk), CEO communications dump (Slack), leaked PowerPoints (corporate intranet).

**App shape:** a familiar interface (Gmail clone, Slack clone, file browser) loaded with the entity's content. The interface itself is the joke.

**Slots:**
- The interface skin (which familiar UI to mimic)
- The named entity ("logged in as ...")
- The content list (emails, messages, files)
- The metadata (dates, recipients, subjects)

**Fixed:**
- The interface chrome itself (sidebar, header, item list)
- Routing patterns

**Caution:** parody UIs that mimic specific commercial products invite trademark concerns. The mill produces *generic-looking* email clients, not literal Gmail clones. Visual signal of the genre, not pixel reproduction.

## Archetype 3: Case-file browser

**When it fits:** the input involves qualitative document releases without inherent numerical structure. PDFs, transcripts, witness statements, redacted reports.

**Examples:** UAP files released on a rolling basis, declassified Cold War cables, court filings, FOIA responses.

**App shape:** a documents list, a reading pane, search/filter by date and tags, a "next case" button.

**Slots:**
- Case list with titles, dates, classification levels
- Document text or excerpts
- Tags and filters
- The investigator persona ("Welcome, Analyst")

**Fixed:**
- Two-pane layout (list left, reader right)
- Search and filter UI

## Archetype 4: Counter game

**When it fits:** the input is an absurd viral phrase, gesture, or repeated action with no inherent meaning.

**Examples:** "67", skibidi, fanum tax, any phrase that has gone viral as nonsense.

**App shape:** a button, a counter, a leaderboard, optionally a webcam-based gesture detector. The user does the absurd thing as many times as possible.

**Slots:**
- The phrase or action
- The counter copy ("how many times have you 67'd today?")
- The leaderboard schema
- Optional: gesture detection logic (MediaPipe-style) if the input warrants it

**Fixed:**
- Counter UI primitives
- Leaderboard primitives (in-memory only for V0; no backend persistence)

## Archetype 5: Disruption visualizer

**When it fits:** the input describes a choke point, blockage, or single-source dependency whose disruption produces ripple effects.

**Examples:** Strait of Hormuz shipping, Suez Canal blockage, single-supplier semiconductor disruption, undersea cable cut, single-port-of-entry shutdown.

**App shape:** a flow diagram showing the source, the choke point, and the downstream dependents. Animated arrows or pulses showing the disruption.

**Slots:**
- The source node label
- The choke point label
- The downstream consumer nodes (countries, industries, products)
- The volume metric (barrels/day, TEUs/month, etc.)
- The disruption magnitude

**Fixed:**
- The diagram primitive (SVG-based)
- The flow animation

## Archetype 6: Diaspora map

**When it fits:** the input describes a scattered group whose tracing is itself the story.

**Examples:** cruise ship passengers spread across nationalities, evacuees from a disaster, contacts of an index case, alumni of a closed school.

**App shape:** a world map with pins, each pin representing one individual or group, with a click-to-reveal detail card.

**Slots:**
- The scattering event description
- The pin list with locations and metadata
- The "tracing complete: X of Y" counter

**Fixed:**
- The map component
- The pin and card primitives

## Archetype 7: Legal-action tracker

**When it fits:** the input describes a multi-front legal or political campaign with named cases, defendants, jurisdictions.

**Examples:** trans rights litigation, antitrust filings against a single company, state-by-state abortion laws, civil cases against a public figure.

**App shape:** a kanban-style board grouped by status (filed, pending, ruling, appealed) or jurisdiction.

**Slots:**
- The campaign description
- The case list with metadata
- The status column definitions

**Fixed:**
- The kanban board primitive
- The case card primitive

## Archetype 8: Mutual aid coordinator

**When it fits:** the input describes a service gap (a shutdown, a defunding, a withdrawal) with geographic distribution and a community-organizing response.

**Examples:** FEMA capacity changes, hospital closures, library defunding, public transit cuts, food bank gaps.

**App shape:** a geographic resource map with editable annotations, a "report a gap" form, a "offer help" form.

**Slots:**
- The service domain
- The map regions and their gap severity
- The form fields for gap reports and aid offers

**Fixed:**
- The map primitive
- Read-only forms in V0 (no actual submission persistence)

**Caution:** this archetype produces apps that *look* like they can coordinate real aid. The footer disclaimer and the lack of submission persistence make clear they cannot. Important: the satire does not stand in for real coordination tools.

## Archetype 9: Wordle redux

**When it fits:** the input has a finite, well-defined entity space that can be guessed via attribute clues.

**Examples:** "guess the senator from their voting record," "guess the country from its imports," "guess the executive from their compensation package."

**App shape:** a daily puzzle with a single answer, attribute hints revealed on each guess, a streak counter.

**Slots:**
- The entity domain (senators, countries, executives)
- The attribute hint set
- The daily answer rotation logic (deterministic from date)

**Fixed:**
- The guess input UI
- The hint reveal animation
- The streak counter

## Archetype 10: Glorified to-do

**When it fits:** the input describes a small life-utility or preparedness checklist with a clear domain.

**Examples:** "things to pack for a hurricane," "what to do in the first hour after a layoff," "checklist for a job interview at a specific company."

**App shape:** a checklist app with check-off persistence (in browser localStorage, not server).

**Slots:**
- The checklist domain title
- The checklist items
- Optional groupings or phases

**Fixed:**
- The checklist UI primitive
- localStorage persistence

**Caveat:** localStorage is not allowed in artifacts that must run on Claude.ai's artifact sandbox, but is acceptable in deployed Vercel apps. Generated apps run on Vercel, so localStorage is fine.

## Archetype 11: Glorified social

**When it fits:** the input describes a niche community whose primary need is communication, posting, or sharing.

**Examples:** "Twitter for cruise ship survivors," "Reddit for declassified UFO researchers," "Discord for a specific protest movement."

**App shape:** a feed UI with a post composer and a list of (mock) posts.

**Slots:**
- The community description
- The mock post seed data
- The composer placeholder copy

**Fixed:**
- The feed UI primitive
- The composer (read-only in V0; no actual posting persistence)

**Critical:** generated social apps must NOT accept real user posts in V0. They are display artifacts. The composer can be styled but submission is a no-op.

## Archetype 12: Recommendation engine

**When it fits:** the input has a "given my preferences, what should I X" structure with a finite recommendation domain.

**Examples:** "AI picks your senator's next vote," "recommend a country to flee to based on your politics," "match you with a defunct social network."

**App shape:** a multi-step preference form, a "calculating..." animation, a single recommendation reveal with rationale.

**Slots:**
- The preference question set
- The recommendation pool
- The rationale template

**Fixed:**
- The multi-step form UI
- The reveal animation

## How to score an input against an archetype

The matcher reads the input (a news headline + summary, or a user prompt) and asks for each archetype: *given the spirit and example domains above, how well does this input fit?*

A high score (8-10) means the input is a near-prototypical example of the archetype. A medium score (5-7) means it could plausibly produce an app of this archetype but it would be a stretch. A low score (0-4) means the archetype is wrong for this input.

The threshold for selection is 7. Below that, no archetype is selected and the input is rejected with reason `no archetype match`.

If multiple archetypes tie at or above 7, the matcher picks one at random (with a uniformly distributed dice roll), and the rejection log preserves the tied scores for the rejection sidebar to display.

## Cross-archetype principles

Regardless of archetype, every generated app must include:

- A footer disclaimer in fixed copy (see `VOICE.md` for exact text)
- A `meta` tag identifying it as Vibe Mill output: `<meta name="generator" content="Vibe Mill">`
- A favicon that is the Vibe Mill mark (not a custom favicon per archetype)
- No analytics or tracking beyond Vercel's default
- No external API calls at runtime (data is baked in at build time)
- No localStorage in V0 except for Glorified to-do (archetype 10)

These constraints ensure consistency across the cemetery and prevent generated apps from doing anything surprising at runtime.
