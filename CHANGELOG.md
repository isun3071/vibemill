# Changelog

Reverse-chronological history of Vibe Mill changes that materially shifted the project's shape. Bundle labels are used for grouped feature releases; semantic-version-style `v3/v4/v5/v6` labels are older history.

## Bundle K — Tier spread + commit-history story-fidelity

- **Banger distinguisher requirement** (Lever 1) injected into `_TIER_FILE_GUIDANCE["banger"]`. Forces one specific killer feature beyond the CRUD baseline. Anti-examples listed (dark mode, generic about page, stats counter, "powered by" badge); pro-examples listed (search affordances, share/export flows, view-mode toggles, undo/redo, guided onboarding). Leans on the model's training distribution to identify what makes Best Overall winners win.
- **`polish_for_banger()` second pass** (Lever 3). After a successful build, the banger output runs through `prompts/generator/polish.txt`. The polish prompt sees the full first-pass file set and is asked to add ONE additional visible improvement: UX flourish, copywriting pass, secondary interaction, demo-flow improvement, specificity in seed data, or visual hierarchy fix. Safe fallback at three points: parse failure, static analysis failure, build failure all keep the pre-polish output. Pre-polish artifact is guaranteed-good (it built); polish can only improve or be discarded.
- **Tier-driven commit count + window** in `github_publish.py`. Slop 2-3 commits over 8-12h; mean_good 5-7 commits over 18-30h; banger 9-14 commits over 30-48h. Window scales the apparent hackathon duration, signaling tier through the GitHub timeline view as well as through the artifact.
- **Substrate-aware random commit tweaks**. nextjs uses Tailwind class number bumps + JS comments; flask tweaks CSS px values, HTML comments, or Python comments depending on file type; gradio appends Python comments. Replaces the JS-only Tailwind regex that previously produced empty-diff intermediate commits on Python archetypes.
- **Archetype-agnostic middle commit messages**. Replaced tracker-specific entries ("add tracker dashboard", "hook up the chart", "add map panel") with neutral phrasings that fit any archetype ("wire up the form", "actually save to db", "fix the routes", "wire up auth").
- **Progressive file additions across commits**. The required file (`app.py` / `app/page.tsx`) and stack-baseline files (`requirements.txt` / `package.json` / `.env.example`) land in commit 0; remaining files spread across middle commits; `README.md` + `mlh.md` appear only in the final commit (real teams write the pitch artifact at the end of the hackathon).
- Public-site additions: pagination on the home grid (12 per page, `?page=N` URL state), Black Country engraving backdrop on hero (low-opacity wood engraving + dark-mode invert), mill-status indicator (active/idle state derived from last shipped, ticking countdown to next batch derived from `lastShipped + INTERVAL_HOURS`).
- Operator-experience additions: heartbeat logging in `clients/openrouter.py` (`still waiting (Ns elapsed)` every 60s during long LLM calls).

## Bundle J — mlh.md sidecar + operational disclaimer prepend

- Every repo now ships with both `README.md` (whichever persona was rolled) and `mlh.md` (always the `mlh_template` Devpost-format persona). Real hackathon repos commonly have both; the mill reproduces that artifact stack.
- `mlh_template` pulled from the README rotation pool. Its 0.07 weight absorbed into `enthusiastic` (closest in voice). Rotation now 11 personas instead of 12. `MLH_SIDECAR_PERSONA` constant identifies which prompt the mlh writer uses.
- `mlh.md` gets an explicit **oversell preface**: EXPLICITLY ALLOWED and ENCOURAGED to fabricate feature claims, list libraries not in requirements.txt, claim WebSocket/Redis/Celery/Plaid/Stripe integrations, write dramatic debugging war stories at 2am, claim "Series A: we're already talking to angel investors," etc. README stays honest about the code; mlh.md gets to perform the genre fully.
- `VIBEMILL_DISCLAIMER` blockquote prepended to every README and mlh.md: *"Generated by Vibe Mill. This repository was produced by an automated pipeline. No human wrote this code. It is not a product and should not be treated as one."* Operational honesty per the project's bounded-satire commitments. Renders below HF Spaces YAML frontmatter when present.
- New `LlmPurpose` literal `"mlh"` for cost-ledger observability so the mlh-pass spend is queryable separately from the README pass.
- Substrate-aware `_mlh_substrate_hint()` injects stack baseline (Python+Flask / Python+Gradio / Next.js) plus an invitation to overlist relatable hackathon tech in the "Built with" section.

## v6 — Bundle I: Flask rail + github_only

Flask rail via `deploy_target=github_only`. Seven previously-stubbed archetypes (`glorified_todo`, `parody_ui`, `marketplace`, `map_visualizer`, `recommendation_engine`, `game`, `glorified_social`) become buildable as Flask apps that live as GitHub repos only — no Vercel, no HF Spaces. The GitHub repo IS the artifact; visitors clone and run locally. Genre-authentic to a huge slice of the real hackathon corpus that submits as "repo + README + demo video," never deployed. Database (SQLite, Postgres), auth (Flask-Login, OAuth), and file storage are now allowed in generated code because the mill never collects real user data — the app never runs on mill infrastructure. README setup steps are part of the artifact; tier drives DB use (slop=none, mean_good=optional, banger=required). `SUBSTRATE_BY_ARCHETYPE` values switched from `js`/`python` to stack names (`nextjs`/`gradio`/`flask`). New schema column `apps.substrate` (migration 011). All 13 archetypes from the Bundle F taxonomy are now buildable.

## v5 — Bundle H: Python rail (Gradio + HF Spaces)

Python rail. Two new buildable archetypes (`ai_generator`, `ai_agent`) ship as Gradio apps on Hugging Face Spaces instead of Next.js on Vercel. Per-archetype substrate map in `models.SUBSTRATE_BY_ARCHETYPE` drives generator, security, deploy, retire, README writer, and public site. Generated AI apps use bring-your-own-key (reader sets `OPENAI_API_KEY` in the Space's secrets) — broken-until-keyed AI demos are load-bearing satire (genre-authentic for HF Spaces hackathon output). New schema columns: `apps.deploy_target` and `apps.hf_space_url` (migration 010). HF token + username configured via `HF_TOKEN` and `HF_USERNAME` env vars.

## v4 — ANTI_PATTERNS rules 11-13 removed

Removed ANTI_PATTERNS rules 11 (no runtime fetching), 12 (no persistent storage), and 13 (no parallel instances) along with their references in CLAUDE.md. Generated apps may now use `fetch()`, `localStorage`, etc.; broken/flaky network paths are on-brand for the genre. Static analysis still enforces pre-existing safety patterns (`eval`, `child_process`, etc.); `SECURITY_ADDITIONS.md` is gone.

## v3 — Cadence + epigraph update

Updated cadence to every-4-hours (was hourly). Updated thesis epigraph to the more recent Karpathy quote: *"The profession is being dramatically refactored as the bits contributed by the programmer are increasingly sparse and between."*
